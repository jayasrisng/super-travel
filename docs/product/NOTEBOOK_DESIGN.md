# Wonder — Notebook Design System & Editable Agent Checklist

## Product Design Direction

Wonder must look and feel like an old-school handwritten travel journal.

This is the primary design identity across the web application, trip dashboard, wardrobe, Magic and daily briefing.

**Light theme: Paper & Pencil**
- Warm ivory paper background, not pure white.
- Graphite-colored text.
- Very subtle horizontal notebook lines.
- A faded red or pink vertical margin rule.
- Handwritten headings and annotations.
- Pencil-style checkboxes, arrows, underlines and scribbles.
- Soft, understated paper grain.
- Natural spacing, as if written in a personal notebook.

**Dark theme: Blackboard & Chalk**
- Deep charcoal or muted blackboard green.
- Warm off-white chalk text.
- Subtle chalk dust and imperfect strokes.
- Chalk-style checkboxes, arrows and annotations.
- Muted sage and dusty beige highlights.
- Avoid glowing neon effects, glassmorphism and glossy gradients.

Both themes must be readable, accessible, responsive and visually consistent.

Respect system theme preferences and allow users to switch manually.

## Typography

Use a carefully chosen handwritten font for headings, short labels and personal notes. Prefer an open-license font such as Caveat or Patrick Hand, subject to license verification.

Use a highly legible complementary font for longer text, prices, dates, forms and important instructions.

Avoid excessive font variation.

The design should feel genuinely handwritten without sacrificing usability.

## Interaction Design

The interface should behave like an interactive notebook.

- Checking a task draws a natural pencil/chalk checkmark.
- Completed tasks receive a subtle hand-drawn strike-through.
- Adding a task feels like writing on a new notebook line.
- Opening a task reveals an expandable note or paper sheet.
- Agent progress appears as a small handwritten annotation.
- Important actions use simple, unobtrusive controls.
- Avoid unnecessary modals and large dashboard cards.
- Respect reduced-motion settings.

Use CSS and lightweight SVG details rather than large decorative images for notebook effects.

## Editable Checklist System

Every task must support the following fields:

- `id`
- `trip_id`
- `title`
- `description`
- `agent_instructions`
- `assigned_agent`
- `status`
- `priority`
- `due_date`
- `created_by`
- `requires_approval`
- `agent_run_id`
- `result`
- `created_at`
- `updated_at`

Users must be able to:

1. Add custom checklist items.
2. Edit existing task titles.
3. Explain what a task means.
4. Specify what the agent should do.
5. Assign or change the responsible agent.
6. Run or rerun the agent.
7. View agent progress.
8. Review recommendations and supporting sources.
9. Approve or reject proposed actions.
10. Mark tasks complete manually.
11. Reopen completed tasks.
12. Delete or archive tasks.
13. See which tasks were generated by Wonder and which were added manually.

### Custom Task Creation

Example user input:

"Find a vegetarian birthday dinner for my mom in Tokyo."

Wonder should suggest:

**Task title:** Book birthday dinner

**Description:** Find a suitable restaurant for a family birthday celebration.

**Agent instructions:** Research vegetarian-friendly restaurants in Tokyo, prioritize quiet environments, check prices and available reservations, and present three suitable options for approval.

**Assigned agent:** Explore & Experience

**Status:** Ready to start

The user can edit all of these fields.

Do not silently book a restaurant.

### Agent Task Lifecycle

Use the following states:

- Not started
- Queued
- Agent working
- Needs more information
- Ready for review
- Waiting for approval
- Completed
- Failed
- Cancelled

The frontend must display real backend states when available, not simulated activity masquerading as real execution.

An agent may propose a change to a task, but user-edited instructions must not be silently overwritten.

Record the agent's results and relevant execution history.

### Notebook Checklist Layout

Collapsed view:

`☐ Find flights                 ✎ Wonder is researching`

Expanded view:

- Task title.
- What this task means.
- What the agent should do.
- Assigned agent.
- Current status.
- Recommendations or results.
- Approve, edit, rerun or complete actions.

The default view must remain extremely minimal.

Only show detailed information when the user opens the task.

## Apply This Design Everywhere

**Homepage:** A personal notebook cover and a small list of trips.

**Trip dashboard:** A ruled checklist with margin annotations.

**Wardrobe:** A fashion sketchbook with outfit cards, swipe gestures and saved looks.

**Packing list:** A handwritten packing checklist with clothing photo references.

**Magic:** A small handwritten prompt and a few curated experience cards.

**Daily briefing:** A morning note pinned to the notebook.

**Dark mode:** The same information hierarchy recreated as a chalkboard.

## Implementation Requirements

1. Inspect the existing application and preserve working backend functionality.
2. Create reusable design tokens for paper, graphite, chalk, blackboard, rules and annotations.
3. Build shared notebook components rather than styling each screen independently.
4. Implement functional editable checklist CRUD operations and persistence.
5. Integrate agent task execution with the existing backend.
6. Preserve user-authored descriptions and instructions.
7. Support light/dark themes, responsive layouts and accessible interactions.
8. Test task creation, editing, agent assignment, completion, reopening and persistence.
9. Provide screenshots of both themes at desktop and mobile sizes.
10. Do not stop at a visual mockup. Implement the interactions.

**Final design rule:** Wonder should feel like a handwritten notebook that happens to contain a powerful AI travel assistant. The user sees simplicity; the system handles complexity.
